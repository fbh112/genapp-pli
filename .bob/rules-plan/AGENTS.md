# Project Architecture Constraints (Non-Obvious Only)

## Three-Tier LINK Chain — Not Optional
The architecture enforces a strict three-tier chain: `*OL01` (orchestrator) → `*DB01` (DB2) and `*VS01` (VSAM). Adding a new policy type requires creating all three tiers and registering all three programs in the CSD. Bypassing a tier or merging tiers breaks the intended separation.

## VSAM Write Is Always Last
`LGAPDB01` always calls `EXEC CICS LINK LGAPVS01` at the end, after all DB2 inserts succeed. The VSAM store is a secondary/summary store written after DB2 commits. Reordering this breaks consistency.

## Policy Auto-Number Requires `IDENTITY_VAL_LOCAL()`
The POLICY table uses DB2 `GENERATED BY DEFAULT AS IDENTITY`. The generated policy number is retrieved immediately after INSERT via `SET :DB2_POLICYNUM_INT = IDENTITY_VAL_LOCAL()` and propagated back through the COMMAREA as `CA_POLICY_NUM`. Any new ADD flow must follow this pattern to return the assigned policy number to the caller.

## DB2 CCSID Is EBCDIC Throughout
All tablespaces and tables are created `CCSID EBCDIC`. Do not introduce Unicode string literals or assume ASCII-compatible character handling.

## No Shared State Between Programs
Each CICS LINK is stateless. Programs obtain context entirely from the COMMAREA passed in; there are no shared working-storage areas, no CICS shared containers, and no cross-program global variables. All inter-program data must fit in the 32,500-byte COMMAREA.

## CSD Group Separation
Programs are defined in group `GENASAP`; transactions in `GENASAT`. When adding new programs or transactions, maintain this group assignment to avoid installation failures.

## Error Abend Codes Are Documented Contracts
- `LGCA` = missing COMMAREA (caught by callers checking `CA_RETURN_CODE`)
- `LGSQ` = DB2 sub-table failure triggering backout

These codes may be monitored by operations automation. Do not change or add abend codes without updating operational runbooks.
