Error Handling & Diagnostics Subsystem

1. Overview

The Error Handling & Diagnostics Subsystem covers the operational error handling used by the policy inquiry transaction. The central program is LGIPOL01, a CICS-hosted PL/I program. The subsystem has three parts:

  • Input validation. LGIPOL01 checks that a COMMAREA was supplied (EIBCALEN).
  • Diagnostic logging. The WRITE_ERROR_MESSAGE subroutine builds timestamped error records and sends them to the transient data queue (TDQ) through the shared utility program LGSTSQ.
  • Transaction abend. When a fatal invocation error occurs, the task ends with the abend code LGCA.

The subsystem is deliberately small. It handles one fatal condition, a missing COMMAREA. For that condition it records enough context to diagnose the problem: date, time, program name, customer number, policy number, and a snapshot of the raw COMMAREA. It then stops the transaction.

1.1 Key Capabilities

Capability Mechanism Outcome
Detect missing request payload IF EIBCALEN = 0 Error path is entered
Capture execution context EIBTRNID, EIBTRMID, EIBTASKN copied to WS_TRANSID, WS_TERMID, WS_TASKNUM Context is available for tracing
Timestamp error records EXEC CICS ASKTIME and EXEC CICS FORMATTIME EM_DATE and EM_TIME are populated
Persist diagnostics EXEC CICS LINK PROGRAM('LGSTSQ') Error record and COMMAREA snapshot are written to the TDQ
Terminate abnormally EXEC CICS ABEND ABCODE('LGCA') NODUMP Task ends with a named abend and no storage dump

1.2 Scope

This page covers the error handling parts of LGIPOL01. It also describes the normal-path steps that prepare diagnostic data: return code initialisation and capture of the customer and policy numbers. The policy inquiry business logic is mentioned only where it affects error handling. That includes the call to LGIPDB01 and the HONDA expiry override.

The diagram shows these relationships:

  • LGIPOL01 is the only program that makes error handling decisions. The calling program supplies the COMMAREA and receives the result.
  • WRITE_ERROR_MESSAGE is an internal procedure inside LGIPOL01, not a separate CICS program.
  • LGSTSQ is the only gateway to the TDQ. LGIPOL01 links to it twice during one error event.
  • LGIPDB01 is the database access program. It sits on the normal path and is not part of the error logging path.

2.3 Data Structures Used for Diagnostics

classDiagram class ERROR_MSG { EM_DATE EM_TIME program name LGIPOL01 EM_CUSNUM EM_POLNUM EM_SQLREQ EM_SQLRC EM_MSG_TEXT } class CA_ERROR_MSG { prefix COMMAREA= CA_DATA up to 90 bytes } class COMM_AREA { CA_REQUEST_ID CA_RETURN_CODE CA_CUSTOMER_NUM CA_POLICY_NUM CA_EXPIRY_DATE CA_M_MAKE } class WORKING_STORAGE { WS_TRANSID WS_TERMID WS_TASKNUM WS_CALEN WS_ADDR_DFHCOMMAREA } COMM_AREA --> ERROR_MSG : customer and policy numbers COMM_AREA --> CA_ERROR_MSG : raw bytes via COMM_AREA_RAW WORKING_STORAGE --> ERROR_MSG : execution context

ERROR_MSG is a union layout. It can hold a freeform message string (EM_MSG_TEXT) or structured transaction details. CA_ERROR_MSG is the second record. It carries the raw COMMAREA content, prefixed with COMMAREA=.

3. Operational Error Handling

3.1 Execution Context Capture

At the start of the main procedure, LGIPOL01 copies the CICS Execution Interface Block (EIB) fields into working storage. This preserves the runtime context for later diagnostics.

EIB Field Working Storage Target Description
EIBTRNID WS_TRANSID 4-character transaction identifier
EIBTRMID WS_TERMID 4-character terminal identifier
EIBTASKN WS_TASKNUM 7-digit CICS task number
EIBCALEN (tested directly) Length of the received COMMAREA

3.2 COMMAREA Validation

The first decision in the program checks whether the caller supplied a COMMAREA. A zero length means the request has no payload, so the program cannot continue.

  • If EIBCALEN = 0, the program sets the message text, calls WRITE_ERROR_MESSAGE, and abends.
  • If EIBCALEN > 0, it continues with normal processing.
PL1 
IF EIBCALEN = 0 THEN
   DO;
      EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
      CALL WRITE_ERROR_MESSAGE;
      EXEC CICS ABEND ABCODE('LGCA') NODUMP;
   END;

3.3 Preparation of Diagnostic Data on the Normal Path

If validation passes, the program prepares the data that any later error record would need:

  1. It initialises CA_RETURN_CODE to '00', which is the default success state.
  2. It records the COMMAREA length in WS_CALEN and resolves the pointer WS_ADDR_DFHCOMMAREA.
  3. It copies CA_CUSTOMER_NUM and CA_POLICY_NUM into EM_CUSNUM and EM_POLNUM.
PL1 
CA_RETURN_CODE = '00';
EM_CUSNUM = CA_CUSTOMER_NUM;
EM_POLNUM = CA_POLICY_NUM;

The identifiers are captured before the LINK to LGIPDB01. Any later call to WRITE_ERROR_MESSAGE will therefore carry accurate customer and policy numbers.
