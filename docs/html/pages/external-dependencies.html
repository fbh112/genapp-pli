External Dependencies & Integrations

The GenApp core insurance application integrates across diverse mainframe subsystems, web gateways, transactional presentation layers, and heterogeneous data persistence stores. This document provides a comprehensive technical reference for all external system dependencies, cross-program communication links, diagnostic transient data queues, and data store interactions underpinning the application.

1. Overview

The GenApp architecture decouples presentation, business orchestration, and data access layers. Communication across these layers is mediated through standard CICS communication areas (COMMAREA), EXEC CICS command-level interfaces, and cross-subsystem program links.

Key architectural integration points include:

  • Presentation Tier: CICS 3270 terminal transactions (SSP1, SSP2, SSP3, SSP4, SSC1) capturing user input.
  • API / Service Tier: CICS Web Services / RESTful JSON gateway transaction (SSST / LGWEBST5) exposing core business functions to distributed clients.
  • Customer Subsystem Integration: Cross-domain transactional dependency linking customer life-cycle management with policy data structures via shared relational schema definitions and referential integrity constraints.
  • Core Business & DAL Programs: Orchestrators (LGAPOL01, LGDPOL01, LGIPOL01, LGUPOL01) routing requests to relational Db2 data access modules (LGAPDB01, LGIPDB01, etc.) and synchronized VSAM data stores.
  • Diagnostic & Queue Services: Centralized error capture routing diagnostic messages to CICS Transient Data Queues (TDQ) and Temporary Storage Queues (TSQ) via the LGSTSQ utility program.

The presentation layer and external REST APIs pass transaction requests wrapped within a unified 32,000-byte COMM_AREA structure. Business orchestrators validate input presence, enforce application-level business constraints, delegate database persistence to specialized Data Access Layer (DAL) modules, and log exceptions to LGSTSQ.

3. External Systems and Component Interdependencies

3.1 CICS 3270 User Interface Systems & Transactions

The policy modules serve as the backend execution layer for interactive BMS terminal transactions defined in the CICS System Definition (GenApp.CSD):

  • Transaction SSP1 (LGTESTP1): Menu driver for Motor and General Policy screens. Formats BMS map buffers and executes EXEC CICS LINK to policy orchestrators including LGIPOL01 (Inquiry), LGAPOL01 (Add), LGDPOL01 (Delete), and LGUPOL01 (Update).
  • Transactions SSP2, SSP3, SSP4 (LGTESTP2, LGTESTP3, LGTESTP4): Dedicated menu drivers for Endowment/Life (SSP2), House/Property (SSP3), and Commercial Insurance (SSP4). These programs map BMS terminal input fields into the LGCMAREA communication area and invoke core policy orchestrators.
  • Transaction SSC1 (LGTESTC1): Dedicated terminal transaction driving customer profile maintenance workflows.

3.2 Customer Subsystem Cross-Domain Integration

The Policy domain operates in close coordination with the Customer subsystem, sharing transactional contexts and database constraints:

  • Customer Companion Programs: LGACUS01 (Add Customer), LGICUS01 (Inquire Customer), and LGUCUS01 (Update Customer) along with their corresponding DAL modules (LGACDB01, LGACDB02, LGICDB01, LGUCDB01, LGACVS01, LGICVS01 under transaction LGCF, and LGUCVS01).
  • Database Referential Integrity Coupling:
    • The Db2 POLICY table defines a foreign key on customerNumber referencing CUSTOMER(customerNumber) with ON DELETE CASCADE.
    • Deleting or updating customer records cascades to associated policy rows.
    • Policy inquiry DAL modules (e.g., LGIPDB01) query the CUSTOMER table concurrently with POLICY tables to join customer profile data into the returning COMMAREA.

3.3 Web Services & Modern API Gateway Integration

  • Transaction SSST (LGWEBST5):
    • Exposes GenApp core business functions as CICS Web Services and RESTful JSON endpoints.
    • Ingests JSON/HTTP payloads from external microservices or web applications, deserializes the JSON data into standard 32KB binary LGCMAREA structures, and executes EXEC CICS LINK calls directly against backend orchestrators (LGIPOL01, LGAPOL01, LGICUS01, etc.).

3.4 Operational, Diagnostic & Monitoring Systems

  • Diagnostic Logging Subsystem (LGSTSQ):
    • Centralized logging subprogram invoked across all business logic and DAL components (LGAPOL01, LGIPOL01, LGIPDB01, LGAPVS01).
    • Invoked via EXEC CICS LINK PROGRAM('LGSTSQ') to write structured timestamped error headers (ERROR_MSG) and raw COMMAREA payload snapshots (CA_ERROR_MSG) to CICS Transient Data Queues (TDQ) or Temporary Storage Queues (TSQ).
  • Transaction LGST (LGASTAT1):
    • Gathers and monitors runtime statistics, transaction throughput, and resource utilization metrics across GenApp components and Db2 data sources.
  • Transaction LGSE (LGSETUP):
    • System initialization program responsible for establishing working environment parameters, allocating temporary storage buffers, and initializing shared diagnostic queues.

3.5 VSAM Fast-Path & Mirroring Systems

  • Transaction LGPF (LGIPVS01):
    • Provides optimized fast-path inquiry lookups by querying the primary key index on VSAM KSDS dataset KSDSPOLY, avoiding relational Db2 SQL engine overhead.
  • Data Mirroring & Synchronization:
    • Update, insert, and delete orchestrators call VSAM DAL modules (LGAPVS01, LGDPVS01, LGUPVS01) following Db2 operations to maintain data consistency between relational tables and the KSDSPOLY key-sequenced dataset.

5. Integration Code Examples and Data Contracts

5.1 CICS Inter-Program Linkage (EXEC CICS LINK)

Business logic programs interact with data access layer programs via synchronous CICS program links, passing a fixed 32,000-byte communication area:

PLI 
/* Invoke backend Db2 Data Access program LGIPDB01 */
EXEC CICS LINK PROGRAM(LGIPDB01)
               COMMAREA(COMM_AREA)
               LENGTH(32000);

5.2 Diagnostic and Transient Data Queue Logging Invocation

When error conditions or validation exceptions occur, orchestrators format diagnostic records and link to LGSTSQ to record the incident into CICS Transient Data Queues:

PLI 
/* Capture timestamp for error tracing */
EXEC CICS ASKTIME(ABS_TIME);
EXEC CICS FORMATTIME ABSTIME(ABS_TIME)
                     MMDDYYYY(DATE1)
                     TIME(TIME1);

EM_DATE = DATE1;
EM_TIME = TIME1;
EM_PGM  = 'LGIPOL01';

/* Send formatted error record to TDQ via LGSTSQ */
EXEC CICS LINK PROGRAM('LGSTSQ')
               COMMAREA(ERROR_MSG)
               LENGTH(80);

/* Conditionally write raw COMMAREA snapshot */
IF EIBCALEN > 0 THEN DO;
    IF EIBCALEN < 91 THEN
        CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
    ELSE
        CA_DATA = LEFT(COMM_AREA_RAW, 90);

    EXEC CICS LINK PROGRAM('LGSTSQ')
                   COMMAREA(CA_ERROR_MSG)
                   LENGTH(100);
END;

5.3 Communication Area Interface Contract (LGCMAREA)

The shared data layout contract defined in copybook LGCMAREA mediates data exchange across UI transactions, web gateways, orchestrators, and DAL programs:

PLI 
/* Inter-Program Communication Area Definition (Excerpt) */
DECLARE
  1 COMM_AREA BASED(COMM_AREA_PTR),
    2 CA_REQUEST_ID        CHAR(6),
    2 CA_RETURN_CODE       CHAR(2),
    2 CA_CUSTOMER_NUM      PIC '9(10)',
    2 CA_POLICY_NUM        PIC '9(10)',
    2 CA_ISSUE_DATE        CHAR(10),
    2 CA_EXPIRY_DATE       CHAR(10),
    2 CA_PAYMENT           PIC '9(6)',
    2 CA_POLICY_DETAILS,
      3 CA_MOTOR_POLICY,
        4 CA_M_MAKE        CHAR(15),
        4 CA_M_MODEL       CHAR(15),
        4 CA_M_VALUE       PIC '9(6)',
        4 CA_M_REGMARK     CHAR(7),
      3 CA_ENDOWMENT_POLICY UNION,
        4 CA_E_SUM_ASSURED PIC '9(6)',
      3 CA_COMMERCIAL_POLICY UNION,
        4 CA_B_PROPTYPE    CHAR(255);
