Program Inventory Summary

The GenApp PL/I application is a z/OS CICS transaction processing system designed for comprehensive insurance policy management across four core policy lines: Endowment, House, Motor, and Commercial. This document provides an exhaustive inventory of all 11 PL/I application programs, supporting external/utility modules, interface structures, and persistent data stores that comprise the GenApp architecture.

1. Overview

GenApp processes online policy lifecycle events via a decoupled, multi-tier CICS architecture executing under transaction ID SSP1 and resource group GENASAP. The core business capability spans four basic CRUD operations: Add, Inquire, Delete, and Update.

Inter-program coordination across application boundaries relies on a standardized, shared 32,500-byte communication area (COMM_AREA) defined in copybook LGCMAREA.inc and transferred using standard EXEC CICS LINK or EXEC CICS DYNAMIC_LINK protocols.

2. System Architecture

GenApp follows a strict 3-tier CICS application model separating user presentation, business rules/orchestration, and persistent data access. The persistence layer implements a dual-store paradigm where DB2 acts as the primary system of record while a VSAM Key-Sequenced Data Set (KSDSPOLY) maintains a synchronous copy.

2.1 Architectural Characteristics

  • Uniform Presentation Entry: Transaction SSP1 triggers program LGTESTP1, which manages terminal screen I/O via Basic Mapping Support (SSMAP).
  • Dynamic vs. Static Inter-Program Calls: Standard operations utilize static EXEC CICS LINK, whereas inquiry (LGIPOL01 -> LGIPDB01) and deletion (LGDPOL01 -> LGDPDB01) use dynamic CICS linking where program identifiers are resolved at runtime.
  • Dual Persistence Management:
    • On Add, LGAPDB01 writes to relational tables while LGAPVS01 can be invoked for direct VSAM storage.
    • On Delete, LGDPDB01 executes relational deletes and cascades by calling LGDPVS01 to remove corresponding VSAM entries.
    • On Update, LGUPDB01 performs DB2 updates and subsequently calls LGUPVS01 to synchronize the VSAM record.
  • Centralized Diagnostic Logging: All 11 PL/I modules link directly to external utility LGSTSQ upon trapping errors to log operational diagnostics to a CICS Transient Data Queue (TDQ).

3. Program Inventory Catalogue

3.1 Presentation Tier

3.1.1 LGTESTP1

  • File: PLI Programs/LGTESTP1.pli
  • Role: Presentation controller and terminal user interface dispatcher for the motor policy menu. Captures terminal operator inputs (BMS map SSMAPP1), sets up the COMM_AREA, executes HANDLE AID and HANDLE CONDITION for flow control, and triggers downstream business logic routines via EXEC CICS LINK. Also manages transaction rollback using EXEC CICS SYNCPOINT ROLLBACK.
  • Includes:
    • SSMAP.inc (%INCLUDE SSMAP) — Map definitions for screen I/O fields.
    • LGCMAREA.inc (%INCLUDE LGCMAREA) — Standard 32,500-byte communication block.
  • Target Invocations:
    • LGAPOL01 (Add Policy via PF Key)
    • LGIPOL01 (Inquire Policy via PF Key)
    • LGDPOL01 (Delete Policy via PF Key)
    • LGUPOL01 (Update Policy via PF Key)
    • LGSTSQ (Error Logging)

3.2 Business Logic Tier

3.2.1 LGAPOL01

  • File: PLI Programs/LGAPOL01.pli
  • Role: Business logic controller for policy creation. Validates input parameters in COMM_AREA, optionally calls ODM business rule engine (LGAPBR01), and links to LGAPDB01 for DB2 creation or LGAPVS01 for VSAM creation.
  • Includes: LGCMAREA.inc, LGPOLICY.inc, SQLCA.
  • Target Invocations: LGAPDB01, LGAPVS01, LGAPBR01 (conditional), LGSTSQ.

3.2.2 LGIPOL01

  • File: PLI Programs/LGIPOL01.pli
  • Role: Business logic coordinator for policy inquiries. Inspects inquiry keys in COMM_AREA and invokes LGIPDB01 using dynamic program linking.
  • Includes: LGCMAREA.inc, LGPOLICY.inc.
  • Target Invocations: LGIPDB01 (Dynamic Link), LGSTSQ.

3.2.3 LGDPOL01

  • File: PLI Programs/LGDPOL01.pli
  • Role: Business logic controller for policy deletion. Validates incoming deletion criteria and initiates dynamic link to LGDPDB01.
  • Includes: LGCMAREA.inc, SQLCA.
  • Target Invocations: LGDPDB01 (Dynamic Link), LGSTSQ.

3.2.4 LGUPOL01

  • File: PLI Programs/LGUPOL01.pli
  • Role: Orchestrates policy updates across policy fields. Validates modified parameters passed through COMM_AREA and routes request to LGUPDB01.
  • Includes: LGCMAREA.inc (via COMM_AREA_PTR).
  • Target Invocations: LGUPDB01, LGSTSQ.

3.3 DB2 Data Access Tier

3.3.1 LGAPDB01

  • File: PLI Programs/LGAPDB01.pli
  • Role: Executes DB2 relational inserts. Performs an insert to the POLICY master table, inserts into the subtype table (ENDOWMENT, HOUSE, MOTOR, or COMMERCIAL), inserts initial tracking rows into CLAIM, and reads back generated keys via SELECT.
  • Includes: LGCMAREA.inc, LGPOLICY.inc, SQLCA.
  • DB2 Operations:
    SQL 
    INSERT INTO POLICY (...) VALUES (...);
  INSERT INTO MOTOR (...) VALUES (...);
  INSERT INTO CLAIM (...) VALUES (...);
  SELECT POLICYNUMBER FROM POLICY WHERE ...;
  • Target Invocations: LGSTSQ.

3.3.2 LGIPDB01

  • File: PLI Programs/LGIPDB01.pli
  • Role: High-complexity inquiry module (cyclomatic score 70 across 15 procedures). Uses explicit SQL cursors to fetch matching data across POLICY, policy-type tables (ENDOWMENT, HOUSE, MOTOR, COMMERCIAL), and CLAIM. Utilizes CICS Containers (GET CONTAINER, PUT CONTAINER) to pass bulk payload data.
  • Includes: LGCMAREA.inc, LGPOLICY.inc, SQLCA.
  • DB2 Operations: Cursor OPEN, FETCH, CLOSE across POLICY, COMMERCIAL, and CLAIM; single-row SELECT across ENDOWMENT, HOUSE, MOTOR.
  • Target Invocations: LGSTSQ.

3.3.3 LGDPDB01

  • File: PLI Programs/LGDPDB01.pli
  • Role: Executes relational deletion of policy records. Deletes the primary key from POLICY and cascades execution by calling LGDPVS01 to remove the matching VSAM record.
  • Includes: LGCMAREA.inc, SQLCA.
  • DB2 Operations: DELETE FROM POLICY WHERE POLICYNUMBER = :HV-POLICY-ID.
  • Target Invocations: LGDPVS01 (EXEC CICS LINK), LGSTSQ.

3.3.4 LGUPDB01

  • File: PLI Programs/LGUPDB01.pli
  • Role: Handles relational updates. Obtains row-level locks via SELECT ... FOR UPDATE cursor on POLICY, executes updates on the specific subtype table (ENDOWMENT, HOUSE, MOTOR), updates POLICY, retrieves the updated LASTCHANGED timestamp, and calls LGUPVS01 to synchronize VSAM.
  • Includes: LGCMAREA.inc, LGPOLICY.inc, SQLCA.
  • DB2 Operations: Cursor SELECT FOR UPDATE, UPDATE POLICY, UPDATE ENDOWMENT|HOUSE|MOTOR, SELECT LASTCHANGED.
  • Target Invocations: LGUPVS01 (EXEC CICS LINK), LGSTSQ.

3.4 VSAM Data Access Tier

3.4.1 LGAPVS01

  • File: PLI Programs/LGAPVS01.pli
  • Role: Direct VSAM persistence for policy addition. Writes new records into the KSDSPOLY KSDS file.
  • Includes: LGCMAREA.inc.
  • CICS File Commands:
    PLI 
    EXEC CICS WRITE FILE('KSDSPOLY') FROM(COMM_AREA) RIDFLD(POLICY_KEY) RESP(WS_RESP);
  • Target Invocations: LGSTSQ.

3.4.2 LGDPVS01

  • File: PLI Programs/LGDPVS01.pli
  • Role: Deletes records by key from KSDSPOLY as part of a cascaded delete sequence initiated by LGDPDB01.
  • Includes: LGCMAREA.inc.
  • CICS File Commands:
    PLI 
    EXEC CICS DELETE FILE('KSDSPOLY') RIDFLD(POLICY_KEY) RESP(WS_RESP);
  • Target Invocations: LGSTSQ.

3.4.3 LGUPVS01

  • File: PLI Programs/LGUPVS01.pli
  • Role: Performs synchronized updates to KSDSPOLY. Acquires an exclusive lock using EXEC CICS READ UPDATE and applies changes using EXEC CICS REWRITE.
  • Includes: LGCMAREA.inc.
  • CICS File Commands:
    PLI 
    EXEC CICS READ FILE('KSDSPOLY') INTO(RECORD_AREA) RIDFLD(POLICY_KEY) UPDATE RESP(WS_RESP);
  EXEC CICS REWRITE FILE('KSDSPOLY') FROM(RECORD_AREA) RESP(WS_RESP);
  • Target Invocations: LGSTSQ.

3.5 Supporting and Utility Programs

3.5.1 LGSTSQ

  • Role: Common error logging utility written in COBOL. Formats error diagnostic records and writes them into a CICS Transient Data Queue (TDQ) for operational auditing. Linked by all 11 PL/I modules on error conditions.

3.5.2 LGAPBR01

  • Role: External ODM (Operational Decision Manager) business rule validation engine (COBOL). Invoked conditionally by LGAPOL01 when BUSINESS_RULES = 'Y' to validate policy underwriting constraints using structure LGCMARER.inc.

4. End-to-End Operational Workflows and Data Flows

4.1 Policy Creation Flow (Add Policy)

During policy creation, the UI program captures input data, forwards it to the orchestration layer (LGAPOL01), evaluates business rules if configured, and persists records across DB2 tables with optional VSAM backup.

4.2 Policy Inquiry Flow (Inquire Policy)

Policy inquiry leverages dynamic program linking and CICS containers to handle large payload queries with multi-table joins.

4.3 Policy Deletion and Synchronization Flow

Deletion executes relational deletion in DB2 and cascades to delete the matching physical VSAM record.

4.4 Policy Update and Synchronization Flow

Update obtains explicit DB2 cursor locks via SELECT FOR UPDATE, modifies subtype records, refreshes master table change timestamps, and rewrites the VSAM record.

5. Shared Resources and Data Structures

5.1 Shared Include Files and Data Definitions

PL/I include files define interface contracts and host structures across transactions:

Include File Source Member Consumer Programs Purpose & Structure Description
LGCMAREA Includes/LGCMAREA.inc All 11 PL/I Programs 32,500-byte universal COMM_AREA structure and COMM_AREA_PTR entry pointer.
LGPOLICY Includes/LGPOLICY.inc LGAPDB01, LGAPOL01, LGIPDB01, LGIPOL01, LGUPDB01 Host variable data structures representing all policy entities for embedded SQL operations.
SQLCA System Copybook LGAPDB01, LGDPDB01, LGDPOL01, LGIPDB01, LGUPDB01 Standard SQL Communication Area providing SQLCODE and SQLERRM.
SSMAP Includes/SSMAP.inc LGTESTP1 BMS Symbolic map definitions for screens SSMAPP1 through SSMAPP5 and SSMAPC1.

5.1.1 Interface Definition Sample Pattern

PLI 
/* Standard PL/I Parameter List and Structure Include Pattern */
LGAPOL01: PROCEDURE(COMM_AREA_PTR) OPTIONS(MAIN REENTRANT);
   %INCLUDE LGCMAREA;
   %INCLUDE LGPOLICY;
   EXEC SQL INCLUDE SQLCA;

   DCL COMM_AREA_PTR POINTER;
   /* Inter-program CICS Link Execution */
   EXEC CICS LINK PROGRAM('LGAPDB01')
                  COMMAREA(COMM_AREA)
                  LENGTH(32500)
                  RESP(WS_RESP);

5.2 DB2 Relational Schema

The DB2 storage subsystem organizes policy records into a master-detail structure configured via JCL template DDL/db2cre.jcl:

Table Name Description Accessing Programs Permitted SQL Operations
POLICY Master policy table containing core attributes and timestamps. LGAPDB01, LGIPDB01, LGDPDB01, LGUPDB01 INSERT, SELECT, FETCH (Cursor), SELECT FOR UPDATE, UPDATE, DELETE
ENDOWMENT Policy subtype details for endowment policies. LGAPDB01, LGIPDB01, LGUPDB01 INSERT, SELECT, UPDATE
HOUSE Policy subtype details for residential property coverage. LGAPDB01, LGIPDB01, LGUPDB01 INSERT, SELECT, UPDATE
MOTOR Policy subtype details for automobile coverage. LGAPDB01, LGIPDB01, LGUPDB01 INSERT, SELECT, UPDATE
COMMERCIAL Policy subtype details for business insurance. LGAPDB01, LGIPDB01 INSERT, SELECT, FETCH (Cursor)
CLAIM Historical and active claim tracking entries. LGAPDB01, LGIPDB01 INSERT, SELECT, FETCH (Cursor)

5.3 VSAM File Storage

The application uses a primary Key-Sequenced Data Set (KSDS) for dual-persistence:

  • CICS File Name / DD: KSDSPOLY
  • Dataset Organization: VSAM KSDS (Key Sequenced Data Set)
  • Target Key: Primary Policy Number
  • Program Usage Matrix:
    • LGAPVS01: EXEC CICS WRITE FILE('KSDSPOLY') (Add record)
    • LGDPVS01: EXEC CICS DELETE FILE('KSDSPOLY') (Delete record)
    • LGUPVS01: EXEC CICS READ UPDATE + EXEC CICS REWRITE FILE('KSDSPOLY') (Update record)

5.4 BMS Maps and Terminal Definitions

  • Transaction Identifier: SSP1
  • Mapset Name: SSMAP (Maps/SSMAP.bms)
  • Active Screen Map: SSMAPP1 (Symbolic mappings SSMAPP1I for input and SSMAPP1O for output)
  • Screen Controller: LGTESTP1 uses EXEC CICS SEND MAP('SSMAPP1') MAPSET('SSMAP') and EXEC CICS RECEIVE MAP('SSMAPP1') MAPSET('SSMAP') to manage 3270 data streams. Additional symbolic structures SSMAPP2–SSMAPP5 and SSMAPC1 are reserved in SSMAP.inc.
