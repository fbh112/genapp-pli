LGIPOL01 – Policy Inquiry Program

1. Overview

LGIPOL01 is a CICS-hosted PL/I program that acts as the business logic front-end for an insurance policy inquiry transaction. It is responsible for retrieving full details of an individual insurance policy, supporting four policy types: Endowment, House, Motor, and Commercial.

Upon invocation, the program receives a Communication Area (COMMAREA) containing a customer number and policy number. It validates the presence of the COMMAREA, initialises a success return code, and delegates the actual database retrieval to a backend program (LGIPDB01) via a CICS LINK call. Once data is returned, it applies a business rule override — extending the policy expiry date to 2099-01-01 for any motor policy where the vehicle make is HONDA — before returning control to the caller.

The program also includes robust error-handling logic: it abends the transaction with code LGCA if no COMMAREA is present, and provides a diagnostic subroutine (WRITE_ERROR_MESSAGE) that writes timestamped error messages — including customer number, policy number, and raw COMMAREA content — to a Transient Data Queue (TDQ) via the LGSTSQ utility program.

LGIPOL01 acts as the coordination layer between the calling transaction and the database access program LGIPDB01. It owns the validation, business rule application, and error logging responsibilities, while LGIPDB01 is solely responsible for the DB2 interaction. The LGSTSQ utility is called only on error paths to write structured diagnostic records to a CICS TDQ.

4. COMMAREA Structure

4.1 Overview

The COMMAREA is the sole mechanism for passing data into and out of LGIPOL01. It is defined via the %INCLUDE LGCMAREA copybook as a UNION-based structure anchored by the COMM_AREA_PTR pointer parameter. The same COMMAREA is forwarded in full to the backend program LGIPDB01.

4.2 Input Fields

Field Type Description
CA_RETURN_CODE CHAR(2) Return code; initialized to '00' by LGIPOL01 at entry
CA_CUSTOMER_NUM CHAR(10) 10-digit customer identifier for the policy inquiry
CA_POLICY_NUM CHAR(10) 10-digit policy number to be retrieved
CA_REQUEST_ID CHAR(6) 6-character field identifying the type of request

4.3 Output Fields

Field Type Description
CA_RETURN_CODE CHAR(2) Final outcome code returned from LGIPDB01; default '00'
CA_ISSUE_DATE CHAR(10) Policy issue date in YYYY-MM-DD format
CA_EXPIRY_DATE CHAR(10) Policy expiry date; overridden to 2099-01-01 for HONDA vehicles
CA_PAYMENT NUM(6) Payment amount associated with the policy
CA_M_MAKE CHAR(15) Motor vehicle manufacturer name
CA_E_SUM_ASSURED NUM(6) Endowment sum assured (guaranteed payout)
CA_B_PROPTYPE CHAR(255) Commercial property type classification
DB2_CUSTOMER Structure Customer personal details (name, address, contact) from LGIPDB01

5. Backend Delegation to LGIPDB01

5.1 Invocation

After COMMAREA validation and initialization, LGIPOL01 delegates the actual policy data retrieval to LGIPDB01 via a synchronous CICS LINK call. The full COMMAREA is passed at a fixed length of 32,000 bytes:

PL1 
EXEC CICS LINK Program(LGIPDB01)
           Commarea(COMM_AREA)
           Length(32000);

5.2 Responsibilities of LGIPDB01

LGIPDB01 is the dedicated database access program for this transaction. It receives the COMMAREA containing the customer and policy numbers, queries DB2, and populates the COMMAREA with the full policy record. It handles all four supported policy types:

Policy Type Key Field(s) Populated
Motor CA_M_MAKE, CA_EXPIRY_DATE, CA_ISSUE_DATE, CA_PAYMENT
Endowment CA_E_SUM_ASSURED, CA_ISSUE_DATE, CA_EXPIRY_DATE, CA_PAYMENT
House CA_ISSUE_DATE, CA_EXPIRY_DATE, CA_PAYMENT
Commercial CA_B_PROPTYPE, CA_ISSUE_DATE, CA_EXPIRY_DATE, CA_PAYMENT

5.3 Data Model

The following entity-relationship diagram represents the DB2 tables accessed by LGIPDB01 on behalf of LGIPOL01:

erDiagram DB2_CUSTOMER { int CA_CUSTOMER_NUM string FIRST_NAME string LAST_NAME date DATE_OF_BIRTH string ADDRESS string PHONE_NUMBER string EMAIL_ADDRESS } DB2_POLICY { int DB2_POLICYNUMBER string DB2_POLICYTYPE date DB2_EXPIRYDATE date CA_ISSUE_DATE decimal CA_PAYMENT } DB2_CUSTOMER ||--o{ DB2_POLICY : owns

A single customer (DB2_CUSTOMER) may own one or more policies (DB2_POLICY). The CA_CUSTOMER_NUM and CA_POLICY_NUM in the COMMAREA are used to uniquely identify the policy record to retrieve.

6. Business Rules

6.1 Return Code Initialization

Before any data retrieval occurs, LGIPOL01 initializes the COMMAREA return code to '00', establishing a default success state:

PL1 
CA_RETURN_CODE = '00';

This ensures that if LGIPDB01 completes without error, a success indicator is already in place.

6.2 Honda Vehicle Policy Expiry Date Override

After LGIPDB01 returns the policy data, LGIPOL01 evaluates the motor vehicle make. If the vehicle is a HONDA, the policy expiry date is unconditionally overridden to 2099-01-01, effectively granting indefinite coverage:

PL1 
IF CA_M_MAKE = 'HONDA' THEN
   CA_EXPIRY_DATE = '2099-01-01';

Important behavioural notes:

  • The comparison is case-sensitive and fixed-length (CHAR(15)). The value 'HONDA' is implicitly blank-padded to 15 characters by PL/I semantics; any alternate capitalisation (e.g., 'Honda') will not trigger the override.
  • The override supersedes whatever expiry date was returned from the database.
  • This rule applies only after LGIPDB01 has completed — CA_M_MAKE is populated by the database retrieval.
  • If the policy is not a Motor policy, CA_M_MAKE will not be set to 'HONDA', and the override will not fire.
CA_M_MAKE Value Override Applied? CA_EXPIRY_DATE Result
'HONDA' ✅ Yes 2099-01-01
'FORD' ❌ No Value from DB2 (e.g., 2025-06-30)
'honda' (lower case) ❌ No Value from DB2
Any non-motor policy ❌ No Value from DB2

7. Error Handling

7.1 Communication Area Validation and Abort Handling

The very first action after capturing EIB context is to verify that a COMMAREA was supplied. The length field EIBCALEN is checked:

PL1 
IF EIBCALEN = 0 THEN DO;
   EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
   CALL WRITE_ERROR_MESSAGE;
   EXEC CICS ABEND ABCODE('LGCA') NODUMP;
END;

If EIBCALEN equals zero:

  1. An error message text ' NO COMMAREA RECEIVED' is set.
  2. The WRITE_ERROR_MESSAGE subroutine is called to log the event to the TDQ.
  3. EXEC CICS ABEND is issued with abend code 'LGCA' and NODUMP to terminate the task immediately without generating a dump.

7.2 Diagnostic Logging — WRITE_ERROR_MESSAGE

The WRITE_ERROR_MESSAGE internal subroutine is responsible for formatting and dispatching structured diagnostic records to the CICS TDQ via the LGSTSQ utility. It is invoked on any fatal error path.

flowchart TD A([WRITE_ERROR_MESSAGE Called]) --> B[EXEC CICS ASKTIME\nObtain Absolute Timestamp] B --> C[EXEC CICS FORMATTIME\nFormat to DATE1 and TIME1] C --> D[Populate ERROR_MSG\nDate + Time + Program + Customer + Policy + SQLCODE] D --> E[EXEC CICS LINK LGSTSQ\nSend ERROR_MSG to TDQ] E --> F{EIBCALEN > 0?} F -- No --> Z([Return]) F -- Yes --> G{EIBCALEN < 91?} G -- Yes --> H[Copy EIBCALEN bytes\nfrom COMM_AREA_RAW into CA_DATA] G -- No --> I[Copy first 90 bytes\nfrom COMM_AREA_RAW into CA_DATA] H --> J[EXEC CICS LINK LGSTSQ\nSend CA_ERROR_MSG to TDQ] I --> J J --> Z

Step-by-step behaviour:

  1. Timestamp — EXEC CICS ASKTIME populates ABS_TIME; EXEC CICS FORMATTIME converts it to human-readable EM_DATE (MMDDYYYY) and EM_TIME.
  2. Primary error record — ERROR_MSG is populated with date, time, program name (LGIPOL01), EM_CUSNUM, EM_POLNUM, EM_SQLREQ, and EM_SQLRC; sent to LGSTSQ.
  3. COMMAREA snapshot — If EIBCALEN > 0, up to 90 bytes of raw COMMAREA (COMM_AREA_RAW) are extracted into CA_DATA and sent as a second record to LGSTSQ, prefixed with 'COMMAREA='.

8.2 Paragraph Descriptions

8.2.1 LGIPOL01 (Main Procedure Body)

The primary entry point and business logic controller. It orchestrates the entire inquiry flow from validation through data retrieval to response preparation:

  • Captures EIBTRNID, EIBTRMID, and EIBTASKN into WS_TRANSID, WS_TERMID, and WS_TASKNUM for diagnostic traceability.
  • Validates presence of COMMAREA via EIBCALEN; abends with LGCA if absent.
  • Initialises CA_RETURN_CODE = '00' as the default success state.
  • Records COMMAREA length into WS_CALEN and resolves the pointer WS_ADDR_DFHCOMMAREA from COMM_AREA_PTR.
  • Copies CA_CUSTOMER_NUM and CA_POLICY_NUM into EM_CUSNUM / EM_POLNUM for subsequent diagnostics.
  • Issues EXEC CICS LINK Program(LGIPDB01) passing COMM_AREA at 32,000 bytes.
  • Applies the Honda expiry date override if applicable.
  • Returns via EXEC CICS RETURN.

8.2.2 WRITE_ERROR_MESSAGE (Subroutine)

An internal diagnostic subroutine invoked on fatal error conditions. It:

  • Acquires the current timestamp via EXEC CICS ASKTIME and formats it via EXEC CICS FORMATTIME.
  • Populates ERROR_MSG with date, time, program name, customer number, policy number, and SQLCODE.
  • Links to LGSTSQ to write the primary error record to the TDQ.
  • Conditionally extracts up to 90 bytes of raw COMMAREA into CA_DATA and sends a secondary CA_ERROR_MSG record (prefixed 'COMMAREA=') to LGSTSQ.

10. Constraints

10.1 COMMAREA Presence and Size

  • COMMAREA must be present: EIBCALEN = 0 triggers an immediate LGCA abend — no processing proceeds without a COMMAREA.
  • Backend COMMAREA is fixed at 32,000 bytes: The EXEC CICS LINK to LGIPDB01 hard-codes Length(32000).
  • TDQ error dump is capped at 90 bytes: Only the first 90 bytes of the raw COMMAREA are logged to protect TDQ space.

10.2 Sequencing Constraints

  • CA_RETURN_CODE = '00' must be set before the LGIPDB01 LINK call.
  • The Honda override check must occur after LGIPDB01 returns, as CA_M_MAKE is populated by the database retrieval.
  • EXEC CICS RETURN terminates execution unconditionally — no logic can follow it.

10.3 Business Rule Constraints

  • The Honda comparison is case-sensitive and exact: only the string 'HONDA' (blank-padded to 15 characters) qualifies.
  • The expiry date override replaces the database value entirely.

10.4 Data Format Constraints

  • CA_RETURN_CODE — CHAR(2), must be '00' on initialization.
  • CA_EXPIRY_DATE / CA_ISSUE_DATE — CHAR(10), format YYYY-MM-DD.
  • CA_M_MAKE — CHAR(15); comparison string 'HONDA' is PL/I blank-padded to match.

11. Examples

11.1 Example 1: Motor Policy Inquiry — HONDA Vehicle (Expiry Date Override Applied)

Input COMMAREA:

Field Value
CA_CUSTOMER_NUM 0000001234
CA_POLICY_NUM 0000009876

Processing steps:

  1. CA_RETURN_CODE is initialised to '00'.
  2. Customer (0000001234) and policy (0000009876) numbers are copied into the error message structure.
  3. LGIPDB01 is invoked via EXEC CICS LINK and returns CA_M_MAKE = 'HONDA'.
  4. The override rule fires: CA_EXPIRY_DATE = '2099-01-01'.
  5. EXEC CICS RETURN sends the COMMAREA back to the caller.

Output COMMAREA:

Field Value
CA_RETURN_CODE 00
CA_EXPIRY_DATE 2099-01-01
CA_M_MAKE HONDA

11.2 Example 2: Motor Policy Inquiry — Non-HONDA Vehicle (No Override)

Input COMMAREA:

Field Value
CA_CUSTOMER_NUM 0000005555
CA_POLICY_NUM 0000001111

Processing steps:

  1. CA_RETURN_CODE is initialised to '00'.
  2. LGIPDB01 is invoked and returns CA_M_MAKE = 'FORD' and CA_EXPIRY_DATE = '2025-06-30'.
  3. The Honda override check evaluates to false — CA_EXPIRY_DATE retains its database value.
  4. EXEC CICS RETURN sends the COMMAREA back to the caller.

Output COMMAREA:

Field Value
CA_RETURN_CODE 00
CA_EXPIRY_DATE 2025-06-30
CA_M_MAKE FORD

11.3 Example 3: Missing COMMAREA — ABEND Triggered

Input: Transaction invoked with no COMMAREA (EIBCALEN = 0).

Processing steps:

  1. EIBCALEN = 0 check is true.
  2. EM_MSG_TEXT is set to ' NO COMMAREA RECEIVED'.
  3. WRITE_ERROR_MESSAGE is called — a timestamped error record and a COMMAREA snapshot are written to the TDQ via LGSTSQ.
  4. EXEC CICS ABEND ABCODE('LGCA') NODUMP is issued — task terminates abnormally.

Expected output: Transaction abends with code LGCA. An error record containing the date, time, program name LGIPOL01, and the text NO COMMAREA RECEIVED is written to the diagnostic TDQ. No policy data is returned.
