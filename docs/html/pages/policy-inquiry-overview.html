Policy Inquiry Functional Domain

The Policy Inquiry Functional Domain encompasses the end-to-end processing pipeline for retrieving and presenting insurance policy details across four distinct policy lines: Endowment, House, Motor, and Commercial. At the heart of this domain is the CICS-hosted PL/I program LGIPOL01, which acts as the business logic front-end, coordinating communication area validation, backend database delegation, business rule enforcement, and error diagnostics. This domain ensures that customer service representatives and downstream systems can reliably retrieve current policy contracts for any supported policy type.

1. System Architecture

The Policy Inquiry domain follows a layered architecture pattern: a business logic tier (LGIPOL01) sits between the calling transaction and a dedicated database access tier (LGIPDB01), with a shared logging utility (LGSTSQ) providing cross-cutting diagnostic support. All inter-program communication is conducted via the CICS LINK mechanism using a shared COMMAREA structure.

The architecture enforces a strict separation of concerns:

  • LGIPOL01 owns business logic, COMMAREA validation, and business rule application.
  • LGIPDB01 owns all DB2 data access and returns results via the shared COMMAREA.
  • LGSTSQ provides a reusable, decoupled logging mechanism writing to CICS Transient Data Queues.
  • CICS EIB supplies runtime context (transaction ID, terminal ID, task number, COMMAREA length) to LGIPOL01 automatically.

2. Overview

The Policy Inquiry Functional Domain is responsible for handling requests to retrieve the full details of an individual insurance policy. It supports four policy lines:

Policy Type Key Field Description
Endowment CA_E_SUM_ASSURED Guaranteed payout (sum assured) of the endowment contract
House CA_B_PROPTYPE Classification of the insured property
Motor CA_M_MAKE Vehicle manufacturer; drives business rule overrides
Commercial CA_B_PROPTYPE Classification of the insured commercial property

The domain is entered via program LGIPOL01, which accepts a COMMAREA containing a customer number (CA_CUSTOMER_NUM) and a policy number (CA_POLICY_NUM). Upon successful retrieval by the backend program LGIPDB01, the populated COMMAREA — including all policy attributes, customer details, issue date, expiry date, and payment information — is returned to the caller.

A notable business rule within this domain applies specifically to Motor policies: any policy where the insured vehicle make is HONDA receives an unconditional expiry date override to 2099-01-01, representing an indefinite coverage grant.
