Policy Inquiry Program (LGIPOL01)

The LGIPOL01 program serves as the core business logic controller for insurance policy inquiry operations within the GenApp CICS application suite. It retrieves and formats comprehensive contract details across multiple policy categories—including Endowment, House, Motor, Commercial, and Claims. The program acts as an intermediary layer: it validates the caller’s communication area, delegates relational database retrieval to the DB2-tier access program LGIPDB01, applies custom business rules (such as overriding policy expiration dates for specific motor vehicle makes), and coordinates error diagnostics and logging via the transient data queue writer LGSTSQ.

1. Overview

The primary function of LGIPOL01 is to expose a unified policy inquiry interface to calling programs (such as presentation-tier handlers, web services, or batch adapters). It ensures that incoming requests provide a valid communication buffer, initializes state, triggers the back-end database access module, and enforces application-level underwriting rules before handing response data back to the client.

Key capabilities of LGIPOL01 include:

  • Commarea Validation and Guarding: Validates the presence of the CICS Communication Area (EIBCALEN > 0), triggering structured error logging and an abnormal termination (ABEND LGCA) if missing.
  • Data Access Delegation: Dispatches policy and customer data lookups to LGIPDB01 via EXEC CICS LINK, passing a 32,000-byte communication structure.
  • Multi-Type Policy Support: Supports multiple policy domain structures overlaying a single commarea union (CA_ENDOWMENT, CA_HOUSE, CA_MOTOR, CA_COMMERCIAL, CA_CLAIM).
  • Underwriting Exception Handling: Implements an inline motor insurance business rule that extends the expiry date for 'HONDA' vehicles to '2099-01-01'.
  • Diagnostic Logging: Formats execution metadata, SQL request markers, and commarea hex dumps to CICS Transient Data Queues (TDQ) via LGSTSQ.

2. System Architecture

LGIPOL01 operates at the business logic layer in the multi-tier GenApp CICS architecture. It sits between calling front-end/service programs and the back-end DB2 data access layer (LGIPDB01).

3. Communication Area & Data Structures

LGIPOL01 exchanges data through a fixed-size 32,500-byte communication area defined in the LGCMAREA.inc copybook and host variable layouts from LGPOLICY.inc.

3.1 Input / Output Commarea Structure

├── CA_RETURN_CODE       (PIC '99')         - Return status code (00 = Success)
├── CA_CUSTOMER_NUM      (PIC '9999999999') - 10-digit Customer ID

5.2 Step-by-Step Execution Sequence

  1. Environment Capture: The program captures runtime identifiers (EIBTRNID, EIBTRMID, and EIBTASKN) into the working storage header structure WS_HEADER for diagnostic tracing.

  2. Commarea Validation Guard: EIBCALEN is evaluated. If EIBCALEN = 0, the caller passed no data:

    • EM_MSG_TEXT is populated with ' NO COMMAREA RECEIVED'.
    • WRITE_ERROR_MESSAGE is called to log the failure.
    • The transaction terminates immediately with EXEC CICS ABEND ABCODE('LGCA') NODUMP.

  3. Status Initialization & Diagnostic Staging:

    • CA_RETURN_CODE is set to '00'.
    • The commarea address and length are saved in WS_ADDR_DFHCOMMAREA and WS_CALEN.
    • CA_CUSTOMER_NUM and CA_POLICY_NUM are copied to diagnostic fields EM_CUSNUM and EM_POLNUM.

  4. Database Retrieval Delegation (LGIPDB01): EXEC CICS LINK calls program LGIPDB01, passing the COMM_AREA with a length of 32000. LGIPDB01 executes the necessary SQL statements against the DB2 Customer and Policy tables and maps the output into the corresponding commarea structures.

  5. Business Rule Application (Honda Expiry Override): LGIPOL01 evaluates CA_M_MAKE. If it matches 'HONDA', CA_EXPIRY_DATE is unconditionally overwritten with '2099-01-01'.

  6. Return to Caller: EXEC CICS RETURN transfers control back to the invoking program with the populated commarea.

6. Business Rules & Code Implementations

The program encapsulates three specific business rules during policy inquiry processing:

6.1 Rule 1: Initialize Policy Inquiry Return Code

Sets the return code to '00' before database retrieval, establishing an optimistic success state that downstream components can update upon error.

PL1 
CA_RETURN_CODE = '00';

6.2 Rule 2: Delegate Policy Retrieval to Database Program

Transfers execution to LGIPDB01 using CA_CUSTOMER_NUM and CA_POLICY_NUM to fetch policy details from DB2.

PL1 
EXEC CICS LINK Program(LGIPDB01)
           Commarea(COMM_AREA)
           Length(32000);

6.3 Rule 3: Extended Expiry Date Override for Honda Vehicles

Enforces an underwriting exception where motor policies covering 'HONDA' vehicles are granted an indefinite expiration date (2099-01-01).

PL1 
IF CA_M_MAKE = 'HONDA' THEN
   CA_EXPIRY_DATE = '2099-01-01';

7. Error Handling & Diagnostic Logging

7.1 Missing Commarea Guard

If invoked without a commarea (EIBCALEN = 0), LGIPOL01 prevents unmapped memory access by logging the event and issuing a CICS abend:

PL1 
IF EIBCALEN = 0 THEN
  DO;
    EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
    CALL WRITE_ERROR_MESSAGE;
    EXEC CICS ABEND ABCODE('LGCA') NODUMP;
  END;

7.2 Centralized Logging Procedure (WRITE_ERROR_MESSAGE)

The WRITE_ERROR_MESSAGE procedure constructs structured log entries and dispatches them to a CICS Transient Data Queue via the utility LGSTSQ:

  1. Captures system timestamp via EXEC CICS ASKTIME and EXEC CICS FORMATTIME.
  2. Formats ERROR_MSG containing timestamp, program identifier (LGIPOL01), customer number, policy number, SQL request name, and SQLCODE.
  3. Issues EXEC CICS LINK PROGRAM('LGSTSQ') COMMAREA(ERROR_MSG).
  4. If EIBCALEN > 0, extracts a snapshot of the commarea (up to 90 bytes) into CA_ERROR_MSG and issues a second link to LGSTSQ to capture the commarea state.
PL1 
WRITE_ERROR_MESSAGE: PROC;
    EXEC CICS ASKTIME ABSTIME(ABS_TIME);
    EXEC CICS FORMATTIME ABSTIME(ABS_TIME)
              YYYYMMDD(DATE1)
              DATESEP('-')
              TIME(TIME1)
              TIMESEP(':');
    EM_DATE = DATE1;
    EM_TIME = TIME1;
    EXEC CICS LINK PROGRAM('LGSTSQ')
              COMMAREA(ERROR_MSG)
              LENGTH(LENGTH(ERROR_MSG));

    IF EIBCALEN > 0 THEN
      DO;
        IF EIBCALEN < 91 THEN
          CA_DATA = SUBSTR(COMM_AREA_RAW, 1, EIBCALEN);
        ELSE
          CA_DATA = SUBSTR(COMM_AREA_RAW, 1, 90);
        EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(CA_ERROR_MSG)
                  LENGTH(LENGTH(CA_ERROR_MSG));
      END;
END WRITE_ERROR_MESSAGE;

8. Technical Constraints & Dependencies

8.1 Commarea Constraints

  • Total Commarea Length: Fixed at 32,500 bytes (COMM_AREA_RAW).
  • Downstream Call Window: EXEC CICS LINK to LGIPDB01 uses LENGTH(32000), restricting the DB2 retrieval program’s visibility to the first 32,000 bytes.
  • Diagnostic Dump Size: Commarea debug output in WRITE_ERROR_MESSAGE is capped at a maximum of 90 bytes.

8.2 External Program Dependencies

  • LGIPDB01: DB2 data retrieval program. Hard-coded in LGIPOL01 as the sole database delegate.
  • LGSTSQ: CICS Transient Data Queue logging utility used for error and diagnostic reporting.

8.3 Copybook Dependencies

  • LGCMAREA.inc: Defines the universal application commarea union and record layouts.
  • LGPOLICY.inc: Defines DB2 host-variable structures (DB2_CUSTOMER, DB2_POLICY, DB2_MOTOR, etc.).
