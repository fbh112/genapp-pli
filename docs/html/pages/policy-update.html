Policy Update Program (LGUPOL01)

LGUPOL01 is the business logic tier program responsible for validating and coordinating updates to existing insurance policy records within the General Insurance Application (GenApp). Operating within an IBM CICS Transaction Server environment and written in PL/I, it acts as a gatekeeper for policy update requests. The program validates incoming request payloads across three distinct policy domains—Endowment, House, and Motor—verifies data buffer boundaries, enforces mandatory data constraints, records structured diagnostics via a transient data queue logging service, and delegates database persistence to the DB2 data access tier program LGUPDB01.

1. Overview

The primary function of LGUPOL01 is to serve as an intermediary between caller interfaces and the underlying DB2 database tier. When invoked via EXEC CICS LINK, LGUPOL01 receives a shared 32,500-byte Communication Area (COMMAREA). It ensures the integrity of the transaction through the following sequence:

  1. Presence Verification: Inspects the CICS Execution Interface Block (EIBCALEN) to ensure an input buffer was supplied, triggering an abnormal termination (ABEND LGCA) if missing.
  2. Policy Classification & Length Validation: Decodes the operation request code (CA_REQUEST_ID) and computes the required byte length for the specific policy type (Endowment: 152 bytes, House: 158 bytes, Motor: 165 bytes).
  3. Database Delegation: Synchronously links to LGUPDB01 to commit valid policy changes to the DB2 tables.
  4. Diagnostic Logging: In the event of system or input errors, logs structured timestamps, task details, customer and policy numbers, and COMMAREA snapshots to a CICS Transient Data Queue (TDQ) via the LGSTSQ utility program.

2. System Architecture

LGUPOL01 occupies the business logic tier in the modular multi-tier GenApp architecture. It interfaces upstream with client-facing presentation programs and downstream with dedicated database persistence and logging modules.

2.1 Component Interaction

The program coordinates with two key sub-modules:

  • LGUPDB01 (DB2 Update Layer): Invoked via EXEC CICS LINK with the 32,500-byte raw COMMAREA buffer (COMM_AREA_RAW). It executes SQL statements against the DB2 relational tables for the target policy.
  • LGSTSQ (Logging Utility): Invoked during fatal initialisation errors or diagnostic captures to output structured records (ERROR_MSG and CA_ERROR_MSG) to a CICS Transient Data Queue.

3. Program Inputs and Data Structures

3.1 CICS Communications Area (COMMAREA)

The primary interface is passed via pointer parameter COMM_AREA_PTR mapped onto the LGCMAREA copybook structure (LGCMAREA.inc). The total buffer size is fixed at 32,500 bytes (COMM_AREA_RAW).

Request Control and Common Header Fields

  • CA_REQUEST_ID (CHAR(6)): Request code identifying policy type:
    • '01UEND' — Update Endowment Policy
    • '01UHOU' — Update House Policy
    • '01UMOT' — Update Motor Policy
  • CA_RETURN_CODE (PIC '99'): Two-digit status code returned to caller.
  • CA_CUSTOMER_NUM (PIC '9(10)'): Unique 10-digit customer identification number.
  • CA_POLICY_NUM (PIC '9(10)'): Unique 10-digit policy identification number.

Common Policy Attributes (CA_POLICY_REQUEST)

  • CA_ISSUE_DATE (CHAR(10)): Policy issue date passed to the DB2 tier.
  • CA_EXPIRY_DATE (CHAR(10)): Policy expiration date passed to the DB2 tier.
  • CA_LASTCHANGED (CHAR(26)): Timestamp of last record modification.
  • CA_BROKERID (PIC '9(10)'): Broker identifier (nullable in DB2).
  • CA_BROKERSREF (CHAR(10)): Broker reference code (nullable in DB2).
  • CA_PAYMENT (PIC '9(6)'): Premium payment amount (nullable in DB2).

3.2 CICS Execution Interface Block (EIB)

LGUPOL01 retrieves environmental context automatically populated by CICS:

  • EIBCALEN: Inbound COMMAREA byte length, evaluated to ensure buffer integrity.
  • EIBTRNID: 4-byte Transaction ID (copied to WS_TRANSID).
  • EIBTRMID: 4-byte Terminal ID (copied to WS_TERMID).
  • EIBTASKN: 7-digit CICS Task Number (copied to WS_TASKNUM).

3.3 Database Null Indicators

To guard against DB2 SQLCODE errors caused by NULL values when updating database records, three indicator variables are explicitly declared:

  • IND_BROKERID (FIXED BIN(15))
  • IND_BROKERSREF (FIXED BIN(15))
  • IND_PAYMENT (FIXED BIN(15))

4. Program Outputs and Signaling

4.1 Return Codes (CA_RETURN_CODE)

LGUPOL01 signals operational status back to the caller through CA_RETURN_CODE:

CODE 
+--------------------------------------------------------------+
|                    CA_RETURN_CODE Values                     |
+--------------------------------------------------------------+
|  '00' : Success / Clean initial state                        |
|  '98' : Insufficient COMMAREA length for requested policy   |
|  '99' : Unrecognised or unsupported CA_REQUEST_ID            |
+--------------------------------------------------------------+

4.2 DB2 Delegation Payload

When validation succeeds, the full 32,500-byte character COMMAREA (COMM_AREA_RAW) is passed to LGUPDB01. Any return codes or updated column values set by LGUPDB01 remain in the COMMAREA upon return to the calling program.

4.3 Diagnostic Queuing (LGSTSQ)

When logging errors, the program formats two structures and sends them to LGSTSQ:

  1. Primary Diagnostic Record (ERROR_MSG):
    • EM_DATE: Formatted current date (MMDDYYYY) via EXEC CICS FORMATTIME.
    • EM_TIME: Formatted current time (HH:MM:SS).
    • EM_CUSNUM: Customer number from CA_CUSTOMER_NUM.
    • EM_POLNUM: Policy number from CA_POLICY_NUM.
    • EM_SQLREQ: Current SQL operation description.
    • EM_SQLRC: SQLCODE captured at time of failure.
  2. Buffer Diagnostic Record (CA_ERROR_MSG):
    • CA_DATA: Snapshot of the inbound COMMAREA payload (up to 90 bytes).

4.4 CICS Abnormal Termination (ABEND)

If EIBCALEN = 0, LGUPOL01 executes:

PLI 
EXEC CICS ABEND ABCODE('LGCA') NODUMP;

This halts transaction execution immediately, logs the missing COMMAREA state to the TDQ, and suppresses unnecessary dump generation.

5.1 Mainline Processing (LGUPOL01)

The entry point procedure LGUPOL01: Proc(COMM_AREA_PTR) Options(Main) initializes the runtime environment:

  1. Captures EIBTRNID, EIBTRMID, and EIBTASKN into WS_HEADER.
  2. Validates EIBCALEN. If zero, logs " NO COMMAREA RECEIVED" via WRITE_ERROR_MESSAGE and issues ABEND LGCA.
  3. Pre-populates EM_CUSNUM and EM_POLNUM with CA_CUSTOMER_NUM and CA_POLICY_NUM.
  4. Evaluates CA_REQUEST_ID using a SELECT construct:
    • '01UEND': Calculates WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN (28) + WS_FULL_ENDOW_LEN (124) = 152. If EIBCALEN < 152, sets CA_RETURN_CODE = '98' and returns immediately.
    • '01UHOU': Calculates WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN (28) + WS_FULL_HOUSE_LEN (130) = 158. If EIBCALEN < 158, sets CA_RETURN_CODE = '98' and returns immediately.
    • '01UMOT': Calculates WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN (28) + WS_FULL_MOTOR_LEN (137) = 165. If EIBCALEN < 165, sets CA_RETURN_CODE = '98' and returns immediately.
    • OTHERWISE: Sets CA_RETURN_CODE = '99' (allowing fall-through to the database call for downstream rejection).
  5. Invokes UPDATE_POLICY_DB2_INFO and executes EXEC CICS RETURN.

5.2 DB2 Update Invocation (UPDATE_POLICY_DB2_INFO)

Delegates persistence processing to the data access tier:

PLI 
UPDATE_POLICY_DB2_INFO: Proc;
   EXEC CICS LINK PROGRAM('LGUPDB01')
                  COMMAREA(COMM_AREA_RAW)
                  LENGTH(32500);
End UPDATE_POLICY_DB2_INFO;

5.3 Error Handling and Logging (WRITE_ERROR_MESSAGE)

Formats timestamps and dispatches diagnostic log packets:

PLI 
WRITE_ERROR_MESSAGE: Proc;
   EXEC CICS ASKTIME ABSTIME(WS_ABSTIME);
   EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME)
                        DATESEP('/')
                        MMDDYYYY(WS_DATE)
                        TIME(WS_TIME)
                        TIMESEP(':');

   EM_DATE = WS_DATE;
   EM_TIME = WS_TIME;

   /* Write primary structured error message to TDQ */
   EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(ERROR_MSG);

   /* Write COMMAREA snapshot */
   IF ( EIBCALEN > 0 ) THEN DO;
      IF ( EIBCALEN < 91 ) THEN DO;
         CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
      END;
      ELSE DO;
         CA_DATA = LEFT(COMM_AREA_RAW, 90);
      END;
      EXEC CICS LINK PROGRAM('LGSTSQ')
                     COMMAREA(CA_ERROR_MSG);
   END;
End WRITE_ERROR_MESSAGE;

6. Constraints and Validation Rules

6.1 COMMAREA Presence and Buffer Sizing

  • Mandatory Buffer: EIBCALEN cannot be zero. Any unallocated invocation results in an instant ABEND LGCA.
  • Policy Minimum Sizes:
    • Endowment (01UEND): $\ge 152$ bytes ($28\text{ header} + 124\text{ endowment}$)
    • House (01UHOU): $\ge 158$ bytes ($28\text{ header} + 130\text{ house}$)
    • Motor (01UMOT): $\ge 165$ bytes ($28\text{ header} + 137\text{ motor}$)
  • Downstream Buffer Ceiling: Fixed at 32,500 bytes when linking to LGUPDB01.

6.2 Request Identifiers and Policy Types

  • Recognised codes are strictly '01UEND', '01UHOU', and '01UMOT'.
  • Unrecognised codes trigger CA_RETURN_CODE = '99'. The program falls through to LGUPDB01, delegating final validation and failure handling to the DB2 tier.

6.3 Diagnostic Formatting Constraints

  • Error timestamps require sequential execution of EXEC CICS ASKTIME before EXEC CICS FORMATTIME.
  • Primary error messages (ERROR_MSG) must precede COMMAREA data captures (CA_ERROR_MSG).
  • COMMAREA data snapshots are strictly capped at 90 bytes (CA_DATA) to prevent buffer overflows during logging.

7. Execution Examples

7.1 Successful Motor Policy Update

Input COMMAREA

CODE 
CA_REQUEST_ID     : '01UMOT'
CA_CUSTOMER_NUM    : 0000000042
CA_POLICY_NUM      : 0000000007
EIBCALEN           : 165 bytes (28 header + 137 motor data)
Motor Details      : Make, Model, Value, RegNumber, Colour, CC, Manufactured, Premium, Accidents

Execution Path & Result

  1. EIBCALEN > 0: Bypasses abend check.
  2. CA_RETURN_CODE initialised to '00'.
  3. CA_REQUEST_ID matches '01UMOT', requiring 165 bytes. Since EIBCALEN (165) >= 165, validation succeeds.
  4. UPDATE_POLICY_DB2_INFO invokes LGUPDB01 with COMM_AREA_RAW (32,500 bytes).
  5. LGUPDB01 executes DB2 SQL updates and returns control.
  6. LGUPOL01 returns CA_RETURN_CODE = '00' to the caller.

7.2 House Policy Update Rejected (Insufficient Buffer)

Input COMMAREA

CODE 
CA_REQUEST_ID     : '01UHOU'
CA_CUSTOMER_NUM    : 0000000015
CA_POLICY_NUM      : 0000000003
EIBCALEN           : 100 bytes (Requires 158 bytes: 28 header + 130 house data)

Execution Path & Result

  1. EIBCALEN > 0: Bypasses abend check.
  2. CA_RETURN_CODE initialised to '00'.
  3. CA_REQUEST_ID matches '01UHOU', calculating required length of 158 bytes.
  4. Validation check EIBCALEN (100) < 158 evaluates to true.
  5. CA_RETURN_CODE is set to '98'.
  6. Program issues an immediate EXEC CICS RETURN. LGUPDB01 is never invoked, and no database modifications occur.

7.3 Unrecognized Request Code Processing

Input COMMAREA

CODE 
CA_REQUEST_ID     : '01UXXX'
CA_CUSTOMER_NUM    : 0000000099
CA_POLICY_NUM      : 0000000001
EIBCALEN           : 200 bytes

Execution Path & Result

  1. EIBCALEN > 0: Bypasses abend check.
  2. CA_RETURN_CODE initialised to '00'.
  3. SELECT (CA_REQUEST_ID) fails all WHEN clauses and branches to OTHERWISE.
  4. CA_RETURN_CODE is set to '99'.
  5. Execution proceeds to UPDATE_POLICY_DB2_INFO, linking to LGUPDB01 with the '99' return code for DB2-tier handling and resolution.
